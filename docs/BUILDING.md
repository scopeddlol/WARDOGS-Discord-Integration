# Build and release (Windows x64)

End users should run the installer. These instructions are for contributors.

Prerequisites: Python 3.12 x64, Git, [7-Zip](https://www.7-zip.org/), and
[Inno Setup 6](https://jrsoftware.org/isdl.php). The build uses PyInstaller's directory layout
inside an Inno installer, so users receive one setup EXE and can uninstall through Windows.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\packaging\prepare-ocr.ps1
.\.venv\Scripts\python.exe -m pytest -q
.\packaging\build.ps1
```

`prepare-ocr.ps1` downloads the fixed UB Mannheim Tesseract 5.4.0.20240606 Windows distribution,
verifies its SHA-256 against the [winget manifest](https://github.com/microsoft/winget-pkgs/blob/master/manifests/u/UB-Mannheim/TesseractOCR/5.4.0.20240606/UB-Mannheim.TesseractOCR.installer.yaml),
and extracts it without running its installer. No machine-wide OCR installation is needed.
To change the OCR version, review its upstream release and update both URL and hash.

The build copies upstream notices and installed Python package license files into the distribution.
Qt libraries are dynamically linked and remain separate DLLs. Do not replace this with an opaque
single-file packager without reviewing the dependency redistribution requirements.

Outputs:

- `dist/WARDOGS-Discord-Setup.exe`
- `dist/SHA256SUMS.txt`
- `dist/WARDOGS Discord/` (unpacked application)

Use `-Python` or `-ISCC` with `build.ps1` to override tool paths. Use `-SevenZip` with
`prepare-ocr.ps1` if 7-Zip is installed elsewhere.

## Run from source

```powershell
$env:TESSERACT_CMD = "$PWD\vendor\tesseract\tesseract.exe"
.\.venv\Scripts\python.exe desktop_app.py
```

The desktop app stores data in `%LOCALAPPDATA%\WARDOGS Discord`. `WARDOGS_DATA_DIR` can override
that directory for isolated development/tests. The desktop never imports credentials from `.env`;
Start applies the settings entered in its UI. Legacy CLI entry points still support `.env`.

## Verification

Tests cover outbound field filtering, validation, real Windows DPAPI encryption/decryption,
channel-scoped state, deleted-message recovery, rate limits, stop behavior, parser regression,
and desktop controls. Tests mock Discord and game capture; no credentials are needed.

`WARDOGS Discord.exe --smoke-test OUTPUT_DIRECTORY` opens the GUI, records a screenshot, runs the
actual bundled Tesseract against a generated image, writes `smoke.json`, and exits. It does not
load saved credentials, register startup, or connect to Discord. Set `WARDOGS_DATA_DIR` to a
scratch directory for isolated logs. CI also tests install → launch → upgrade → uninstall.

A real match and a bot in a Discord test server are still needed for final end-to-end acceptance:
check initial message creation, in-place updates, each broadcast switch, stop/restart, tray
controls, display calibration, and login startup on Windows 10 and 11. Automated tests cannot
establish OCR accuracy across actual game resolutions or Discord channel permission overrides.

## Releases

Every PR and push builds an installer artifact. To prepare a release after review/merge:
update `AppVersion` in `packaging/installer.iss`, push a matching `v*` tag, and review the draft
release generated by Actions. Download and test the installer before publishing that draft.
The workflow does not publish releases automatically. Code signing is not configured; add a
trusted signing process before broad distribution if you want a verified publisher identity.
